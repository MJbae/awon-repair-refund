## 1. 목표와 제공 범위

임차인이 거주 중 대신 납부한 **장기수선충당금 또는 수선적립금**을 정리하여 소유자인 임대인에게 반환을 요청할 수 있도록 돕는다. 아원데코빌은 별도 관리인 없이 세대가 돌아가며 총무를 맡고, 관리비를 공용 통장으로 모은다. 자동 퇴거 정산이 없는 상황에서도 다른 세대 임차인이 같은 계산기와 법적 근거를 사용할 수 있게 한다.

핵심 흐름은 **호수 선택 → 관리비 납부 시작월·마지막 월 입력 → 계산 금액과 근거 확인 → 월별 상세 확인**이다. 호수 옆에 세대 면적을 작게 표시하고 자동 적용한다. 별도 면적 입력은 없으며 월 적립액은 필요한 경우 옵션에서 변경한다. 기본 기간은 24개월이며 변경할 수 있다. 로그인·서버·유료 API 없이 GitHub Pages에서 동작하도록 만든다.

기본 계산은 **선택 기간의 관리비에 장기수선비가 포함되어 있고, 이용자가 선택한 세대가 면적 비율만큼 납부했다는 가정**으로 한다. 개별 월의 납부 증명이나 관리인 확인을 계산의 선행 조건으로 요구하지 않는다. 실제 대납액 자료를 따로 입력한 경우에는 해당 월에 그 값을 우선한다. 계산 결과는 면적 비례 추정액으로 표시하고 공식 납부확인서로 표현하지 않는다.

**법령 표시에 관한 원칙:** 14세대인 이 건물을 공동주택관리법상 장기수선충당금 대상으로 자동 확정하지 않는다. 집합건물법상 수선적립금일 가능성도 구별한다. 두 제도의 대납금 반환·지급 근거와 면적 기준을 설명하되, 적용 확인을 기본 가정 계산이나 개발의 선행 조건으로 만들지 않는다.

계획에 따른 정적 앱 구현과 자동 검증을 완료했다. 소스는 `site/`, 배포 산출물은 `dist/`이며 실행 방법은 [README](../README.md)에 정리했다. 실제 브라우저 육안 검수와 원격 저장소 연결·배포 상태는 [검증 기록](VERIFICATION.md)에 구분해 남겼다.

호수별 면적 연결은 사용자가 제공한 자료로 확정해 구현한다. 1~4층 나머지 8세대는 402호를 포함해 기존 149.68㎡ 타입으로 연결하며, 14세대 공급면적 합계는 1,763.07㎡이다.

계산에 사용하는 분모는 같은 범위·같은 기준의 세대별 면적 합계이다. 공급면적을 쓰면 1,763.07㎡, 전유면적만의 비율을 쓰면 공개자료상 전용면적 합계 1,591.29㎡가 참고 분모가 된다. 법적 지분 산정에 일부공용부분 조정이 필요하면 별도로 반영한다. 토지 지분이나 주차장 등이 포함된 건물 연면적을 임의로 섞지 않는다. 공식 부과면적이 확인되면 그 자료로 전체 면적표와 분모를 함께 갱신한다.

## 4. 계산 방식

### 4.1 기본 계산과 선택적 보정

| 적용 방식 | 내용 | 화면 표시 |
|---|---|---|
| 기본 | 선택한 각 월의 단지 장기수선비 × 세대 면적 비율. 관리비에 포함해 납부한 것으로 가정 | 면적 비례 추정액 |
| 금액 옵션 | 2024~2026년 기본 월 280,000원을 전체 또는 특정 구간에서 변경 | 수정된 금액을 적용한 추정액 |
| 선택적 실제액 보정 | 이용자가 세대별 실제 대납액을 추가하면 해당 월의 면적 추정액 대신 사용 | 실제 입력액과 추정액을 구분 |

기본 흐름에서는 모든 달의 납부 여부 체크, 관리비 총액 입력, 확인서 업로드를 요구하지 않는다. 이미 반환받은 금액이나 소유자 직접 납부 등 예외를 알고 있는 이용자만 상세 옵션에서 보정한다.

관리비 총액 비율이나 14세대 균등분담으로 적립금을 역산하는 방식은 기본 계산법으로 제공하지 않는다. 관리비에는 청소·전기·승강기 유지비 등 서로 다른 항목이 섞이고, 실제 입금은 납부 시점이나 조정액의 영향도 받기 때문이다.

적용 기준은 다음과 같이 구분한다. 이용자가 더 유리한 금액을 얻기 위해 법령을 임의 선택하는 기능으로 만들지 않고, 확인된 관리자료에 맞춰 설정한다.

| 확인된 제도 | 배분 기준 | 확인 전 동작 |
|---|---|---|
| 공동주택관리법상 장기수선충당금 | 공급면적 비례 | 공급면적 사용 시 가정임을 표시 |
| 집합건물법상 수선적립금 | 규약·관리단결의 확인, 달리 정함이 없으면 법 제12조의 구분소유자 지분 비율 | 전유면적 비율은 일부공용부분 등 지분 조정 여부까지 확인 |
| 제도·부과 기준 미확인 | 공급면적 비례를 초기 계산 가정으로 사용하고, 확인된 자료에 따라 전유면적·지분 기준으로 교체 가능 | `공급면적 비례로 계산한 추정액` 표시, 적용 제도는 별도 설명 |

### 4.2 산식

월 `m`의 단지 해당 적립금 부과·적립 총액을 `Rₘ`, 선택한 동일 기준의 세대 면적을 `Aᵢ`, 전체 대상 세대 면적 합계를 `S`라 하면:

```text
월별 세대 추정액 Eᵢ,ₘ = Rₘ × Aᵢ ÷ S
기간 추정액 = 대상 월별 Eᵢ,ₘ 합계
증빙 기준 정산액 = 대상 기간 중 임차인의 실제 대납액 합계 − 이미 반환받은 금액
```

면적 외에 적법하게 확인된 배분 지분을 적용하는 경우에는 `Rₘ × 확인된 지분`으로 계산한다. 기본 버전은 사용자와 합의한 월 적립액·관리비 포함 납부 가정을 사용하며, 나중에 확인한 실제 자료로 보정할 수 있다. 공동주택관리법상 월 부과액은 장기수선계획의 총수선비·계획기간을 바탕으로 정한다. 임차인의 **24개월 정산 기간**과 건물의 **장기수선계획 기간**은 서로 다르다. 24개월은 서비스 기본값이지 법적 반환 기간 제한이 아니다. 임의로 월 28만 원이 법적으로 적정한 적립액이라고 판정하는 서비스는 아니다. [법정 산식 및 적립액 규정](https://law.go.kr/LSW/lumLsLinkPop.do?chrClsCd=010202&lspttninfSeq=132107)

공급면적 산식 검산 예시: `Rₘ=280,000원`, `Aᵢ=149.68㎡`, `S=1,763.07㎡`를 24개월 모두 동일하게 가정하면 월 약 23,771.26원, 총 **약 570,510원**이다. 전유면적만의 비율 `135.10 ÷ 1,591.29`로 같은 가정을 계산하면 **약 570,526원**으로 달라진다. 두 수치는 산식 예시이며 이 건물의 적용 기준이나 실제 반환액을 확정한 것이 아니다.

실제 납부액과 면적 추정액이 다르면 차이를 표시하고 부과 내역 확인을 안내한다. 실제 대납 기록을 추정액으로 덮어쓰지 않는다. 단지의 현재 적립금 잔액·이미 집행한 공사비를 이유로 개인의 대납액에서 임의 차감하지 않는다.

### 4.3 기간·변동·누락·반올림

- 시작월·마지막 납부월 두 칸으로 기간을 입력한다. 최초 입력 시 반대편 월이 비어 있으면 24개월 범위로 자동 채운다. 이후 한쪽 월을 수정해도 다른 쪽은 유지하며 총개월 수만 갱신한다. `24개월로 맞추기`를 누르면 시작월 기준으로 종료월을 `시작월 + 23개월`로 재설정한다.
- 양 끝 월을 포함한다. 예: 2024-10~2026-09는 24개월이고, 같은 월을 시작·종료로 입력하면 1개월이다. 시작월이 종료월보다 늦으면 그 자리에서 수정 안내를 표시하고 임의로 두 값을 교환하지 않는다.
- 기간 기준은 **관리비 귀속월**이다. 입력 설명은 ‘실제 이체일이 아니라 몇 월분 관리비를 냈는지 선택해 주세요’로 한다. 입주일·퇴거일을 별도로 요구하지 않는다. 선납·후납도 관리비가 해당하는 월에 배정한다.
- `2024-01~2026-12`는 매월 280,000원을 자동 적용한다. 원본 사진이 없는 월도 사용자 승인 가정으로 계산하며, 추가 체크박스나 월별 승인을 요구하지 않는다. 이용자가 선택한 기간과 겹치는 월만 합산한다.
- 2023년·2027년 등 기본 범위 밖의 월은 연속 구간으로 묶어 금액 입력을 제공한다. `이 구간에도 월 280,000원 적용` 또는 직접 입력으로 채울 수 있다. 미입력 구간을 0원으로 처리하거나 2024~2026년 가정을 조용히 확장하지 않는다.
- 금액 옵션은 `선택 기간에 같은 금액 적용`과 `금액이 달라진 기간 추가`를 제공한다. 후자는 시작월·종료월·단지 월 금액만 입력한다. 개별 구간끼리 겹치면 병합·범위 수정 안내를 표시해 중복 적용을 막는다. 구간 경계도 양 끝 월을 포함한다.
- 단지 월 금액의 우선순위는 `개별 월 수정 > 구간 금액 수정 > 선택 기간 일괄 금액 > 2024~2026년 기본값`이다. 일괄 금액 변경으로 개별 수정값을 지우지 않는다. `개별 수정까지 모두 바꾸기`를 명시적으로 실행한 경우에만 덮어쓴다. 실제 세대 대납액을 입력한 월은 면적 배분 결과보다 그 값을 우선한다.
- 기간을 줄여도 범위 밖의 사용자 수정값을 삭제하지 않고 계산에서만 제외한다. 다시 늘리면 복구한다. 호수를 바꾸면 단지 월 금액과 기간은 유지하고 면적 비율만 다시 계산한다. 세대별 직접 입력값은 호수별로 보관하여 다른 호수에 이전하지 않는다.
- 이사월은 기본적으로 선택한 1개월분에 포함한다. 필요한 이용자만 `부분월 조정`에서 실제 정산액 또는 납부 일수 기준의 추정액을 입력한다. 일할 계산은 날짜 양 끝 포함·해당 월 실제 일수 기준을 명시하되 법정 방식으로 표현하지 않는다.
- 선택한 과거·현재 월은 관리비에 포함해 면적 비례로 납부한 것으로 가정한다. 별도로 입력한 소유자 직접 납부·이미 반환받은 금액은 제외한다. 공용 통장의 실제 입금 거래를 기본 계산에 다시 더하지 않아 이중 합산을 막는다.
- 현재 월 이후의 미래 월은 `향후 납부 예상액`으로 분리하고 이미 납부한 금액에 더하지 않는다. 현재 월은 이용자가 납부 기간에 포함한 선택을 따른다. 기본 범위 안의 미래 월에도 28만 원 가정은 사용하지만 결과·출력물에서 예정액임을 표시한다.
- 기본 결과는 `면적 비례 추정액` 하나와 ‘관리비에 포함해 납부한 것으로 계산’이라는 짧은 설명을 표시한다. 실제 입력액·미래 월·금액 미입력 구간이 있을 때만 별도 소계를 펼쳐 보인다. 금액 미입력 월이 있으면 부분 합계와 빠진 개월 수를 표시한다.
- 금액은 원 단위 정수, 면적은 0.01㎡ 단위 정수로 저장한다. 추정 계산은 BigInt 유리수로 합산한 뒤 최종 합계에서 원 단위 반올림한다. 표시용 백분율이나 월 표시액을 반올림해 곱하지 않는다. 실제 부과명세서의 월별 원 단위 값은 원문대로 합산한다. 독립 Fraction 검산·입력 이벤트 회귀·결함 주입 검증은 [계산 정밀도 검증](CALCULATION_AUDIT.md)에 기록한다.
- 이미 반환받은 금액이 대납 추정·입력 합계보다 크면 음수 청구액을 만들지 않고 입력 확인을 요구한다. 확인된 0원과 금액 미입력은 구별한다.

## 5. 반드시 노출할 법적 근거

페이지 최하단에 ‘법적 근거’ 상세 카드를 배치하고, ‘자세히 보기’를 누르면 반환·지급 의무 조항과 원문 링크가 펼쳐지게 한다. 적용 제도 확인 전에는 두 조항을 조건과 함께 제시한다. 조사 시 확인한 공동주택관리법 시행령은 **2026-07-01 시행본**, 집합건물법 시행령은 **2023-09-29 시행본**이다.

**공동주택관리법 시행령 제31조제8항**

> 공동주택의 소유자는 장기수선충당금을 사용자가 대신하여 납부한 경우에는 그 금액을 반환하여야 한다.

[국가법령정보센터 제31조 원문](https://law.go.kr/LSW/lumLsLinkPop.do?chrClsCd=010202&lspttninfSeq=132107)

**집합건물의 소유 및 관리에 관한 법률 시행령 제5조의4제4항**

> 구분소유자는 수선적립금을 법 제5조제4항에 따른 점유자(이하 “점유자”라 한다)가 대신하여 납부한 경우에는 그 금액을 점유자에게 지급해야 한다.

[국가법령정보센터 제5조의4 원문](https://law.go.kr/lumLsLinkPop.do?chrClsCd=010202&lspttninfSeq=165111)

추가 근거는 짧은 설명과 링크로 제공한다.

| 조항 | 서비스에서 설명할 내용 |
|---|---|
| 공동주택관리법 제30조제1항 | 장기수선충당금은 소유자로부터 징수·적립하는 비용 |
| 시행령 제31조제3항 | 월간 세대별 산정은 주택공급면적에 비례 |
| 시행령 제31조제9항 | 사용자가 납부 확인을 요구하면 관리주체는 지체 없이 확인서를 발급해야 함 |
| 집합건물법 제17조의2제3항 | 수선적립금은 구분소유자로부터 징수하며 관리단에 귀속 |
| 집합건물법 시행령 제5조의4제1·2항 | 관리비와 구분해 징수하고, 규약·결의 또는 법정 지분 기준으로 배분 |

[공동주택관리법 제30조](https://www.law.go.kr/법령/공동주택관리법/제30조), [시행령 제31조](https://law.go.kr/LSW/lumLsLinkPop.do?chrClsCd=010202&lspttninfSeq=132107)

소규모·단독동이라는 이유로 대납금 반환 근거가 없다고 판단하지 않는다. 반대로 **승강기가 있다는 사실만으로 공동주택관리법상 장기수선충당금 대상이라고 확정하지도 않는다.** 2025 장기수선계획 실무 가이드라인의 국토부 회신(2017.8, 첨부 PDF 22번째 페이지)은 법 제29조제1항제2·3호의 적용에서 주택법상 사업계획승인 등 요건을 설명한다. 아원데코빌의 인허가 유형과 실제 관리 근거를 확인하고, 공동주택관리법 적용 대상 밖이라면 집합건물법상 수선적립금인지 검토한다. [공동주택관리법 제29조](https://www.law.go.kr/법령/공동주택관리법/제29조), [국토부·LH 2025 실무 가이드라인 배포](https://myapt.molit.go.kr/board/398.do?idx=40024&mode=view)

집합건물법상 징수 주체·근거는 [법 제17조의2](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0017&lsiSeq=249285&urlMode=lsScJoRltInfoR)와 [시행령 제5조의4](https://law.go.kr/lumLsLinkPop.do?chrClsCd=010202&lspttninfSeq=165111)에 따른다. 일반 수선유지비·청소비·전기료를 적립금으로 바꾸어 청구하지 않는다. 통장의 ‘장기수선’이라는 명칭만으로 법적 계정 성격을 확정하지 않는다.

청구 상대는 원칙적으로 비용을 부담해야 할 소유자이다. 법령상 공동주택관리법 경로의 확인서 요청은 제31조제9항에 따르며 그 의무를 집합건물법 경로에 그대로 적용하지 않는다. 다만 이 서비스의 실제 안내에서는 별도 관리인이나 관리사무소가 있는 것으로 가정하지 않는다. 추가 근거가 필요할 때 **당시 또는 현재 총무가 보관한 공용 통장·장기수선 관련 내역을 참고**하도록 설명한다. 총무를 법률상 관리인으로 자동 간주하지 않으며, 확인서를 받아야만 계산·복사할 수 있게 만들지 않는다. 임대차 특약·소유자 변경·이미 이루어진 정산처럼 개별 판단이 필요한 사정은 계산기가 법률적 결론을 자동 확정하지 않는다.

법령 확인일을 화면과 출력물에 표시하고 배포 전 현행 조문을 다시 확인한다. 오래된 안내문의 제31조제7항·제8항 번호를 반환·확인서 조항으로 그대로 복사하지 않는다.

## 6. 최소 UI/UX

모바일에서도 쓰기 쉬운 단일 페이지로 만든다. 호수·납부 기간·계산 결과에 집중하고 금액 변경은 접어서 제공한다. 면적 입력, ‘전용면적과 달라요’ 안내, 정산 내역 복사·인쇄·PDF 저장 버튼은 제거한다.

```text
아원데코빌 장기수선 정산

우리 집 [호수 선택]  149.68㎡
관리비를 낸 기간
시작월 [연도] [월] / 마지막 납부월 [연도] [월]
총 24개월 · 양 끝 월 포함 [24개월로 맞추기]

아파트 전체 적립액에서 우리 집 면적 비율만큼 계산
[계산 기준 확인·변경 ▾]  # 기본 닫힘, 안쪽에 전체 월 적립액 표시
[우리 집 정산액 계산하기]

면적 비례 추정액
[월별 계산 내역 보기       자세히 보기 ▾]
  24개월 · 월별 금액과 조정 내역 확인
  펼치면 면적 비율 설명 + 월별 금액·근거 표

[계산 기준과 자료 출처     자세히 보기 ▾]
  계산식 · 호수별 면적 · 기본 금액의 근거
  펼치면 계산식 → 기본 가정 → 14호 면적표 → 출처

[법적 근거                자세히 보기 ▾]
```

두 상세 영역은 제목·내용 미리보기·명시적인 ‘자세히 보기/접기’와 화살표를 갖춘 전체 행 클릭 카드로 만든다. 기본 `details/summary` 요소를 유지하여 키보드와 보조기술에서 열림·닫힘을 인식할 수 있게 한다. 모바일의 긴 표는 가로 스크롤과 금액 단위 안내를 제공한다.

면적은 호수 선택 옆의 읽기 전용 보조 텍스트이며 입력창이 아니다. 공급·전용 값을 함께 비교하려면 ‘계산 기준과 자료 출처’의 호수별 표를 펼쳐볼 수 있다.

### 납부 기간 입력의 사용성

- 처음 화면의 기준 연도는 현재 연도와 무관하게 2024년으로 고정한다. 연도·월은 모두 드롭다운이고 월은 선택 전 상태로 둔다. 금액 변경 구간의 연·월도 같은 드롭다운을 사용한다. 시작월을 완성하면 마지막 납부월을 23개월 뒤로 자동 채운다. 마지막 월부터 입력하면 시작월을 23개월 전으로 채운다. 자동 채우기는 상대편 값이 비어 있을 때만 한다.
- `시작월`, `마지막 납부월` 두 입력만 상시 노출한다. 편집 가능한 개월 수 입력을 세 번째로 추가하지 않는다. 날짜 달력에서 과거 월까지 반복해서 넘길 필요 없이 연도와 월을 바로 고를 수 있어야 한다.
- 연도와 월은 모두 기본 select 드롭다운으로 선택한다. 2024년을 기준으로 앞뒤 연도를 제공하고 월은 1~12월로 제한한다. 연도 직접 입력·날짜 달력·기본 month 입력창을 사용하지 않는다.
- 모바일에서는 두 월 입력을 세로로 배치한다. 레이블을 입력 밖에 유지하고 44px 이상 터치 영역, 충분한 간격, 논리적인 키보드 이동 순서를 제공한다. 연·월을 입력하는 중에는 계산을 급히 실행하거나 다음 입력으로 강제 이동하지 않는다.
- 완성된 기간 아래에 `2024년 10월~2026년 9월 · 총 24개월 (양 끝 월 포함)`처럼 즉시 요약한다. 시작·종료가 같은 달이면 `총 1개월`로 표시한다. 사용자에게 월 수를 직접 셀 필요가 없게 한다.
- `24개월로 맞추기`는 시작월을 유지하고 마지막 월만 변경한다. 이미 24개월이면 별도 변경 없이 현재 상태를 표시한다. 두 월을 모두 비운 경우에는 먼저 월을 입력하도록 해당 위치를 안내한다.
- 월 미선택·기간 역전은 해당 입력 근처에 구체적으로 표시하고 작성한 다른 값은 유지한다. 잘못된 기간을 자동 교환하거나 종료월을 오늘로 잘라내지 않는다.
- 미래 월을 선택할 수는 있게 하되 기간 요약에 `향후 N개월 포함`을 덧붙이고 계산 결과에서는 향후 예상액을 분리한다. 2024~2026년 밖의 구간도 입력을 막지 않고 해당 구간의 금액 설정으로 연결한다.

월별 상세에서는 전체 월 적립액·우리 집 금액·계산 근거를 표시한다. 화면의 긴 반올림 설명과 반복 안내는 제거하고, 정밀도 검증 내용은 별도 검증 문서에서 관리한다. 실제액만 입력한 결과와 면적 추정이 섞인 결과의 배지를 구분한다. 계산 기준 상세에는 집품·KB 자료 링크만 남긴다. 102호 과거 자료 링크와 ‘추가 내역이 필요하다면’ 안내 문단은 제거한다.

주요 입력에는 레이블과 오류 메시지를 두고 키보드로 조작할 수 있게 한다. 상태를 색깔만으로 구분하지 않는다. 광고·지도·회원가입·관리자 대시보드·자동 발송은 범위에 넣지 않는다.

자료 상태는 `사진 관측 / 공개자료 참고 / 관리자료 확인 / 사용자 입력 / 승인된 기본 가정 / 미확인`으로 구분한다. 원본 판독값, 잔액 대조 결과, 최종 채택값을 덮어쓰지 않고 구분해 보관한다. `reserve-observations.json`의 출금 3건과 `reserve-defaults.json`의 36개월 적용 구간은 별개이며, 가정 파일에 원본에 없는 출금 36건을 만들어 넣지 않는다.

월별 계산표는 `호수·기간 선택 → 승인된 기본 금액 적용 → 단지 금액의 사용자 수정 반영 → 면적 배분 → 세대별 예외 반영` 순서로 만든다. 일괄 적용·구간 수정에는 적용 당시의 시작·종료월을 저장한다. 기간을 나중에 늘려도 수정 구간을 임의 확장하지 않는다. 부분 구간의 금액이 비어 있으면 그 월을 합계에서 누락시킨 사실을 결과에 표시한다. 저장값에는 가정 출처·면적 기준·정산 기준월을 포함하여 계산 결과를 재현할 수 있게 한다.

다른 세대의 납부 이력은 기본 공개하지 않는다. 이용자는 자기 세대의 값을 직접 입력할 수 있다. 향후 공동 자료를 추가할 때도 주민 이름·계좌·납부자 정보를 제거하고 공개에 적합한 부과 기준 자료만 배포 데이터로 선별한다. 화면에서 숨기는 것만으로 정적 JSON을 비공개로 만들 수는 없다.

계산 내용은 현재 페이지 메모리에만 두고 새로고침하면 초기화한다. 기기 저장·삭제 컴포넌트와 하단 서비스명 반복 문구는 제거한다. 이전 버전 브라우저 저장값은 읽거나 변경하지 않는다. 외부 분석 도구나 입력값 전송 기능은 두지 않는다. 공유 URL에는 호수별 납부 내역을 넣지 않는다.

## 8. GitHub Pages 배포 계획

작업 브랜치는 `main`, 원격 `origin`은 `https://github.com/MJbae/awon-repair-refund.git`로 설정했다. 이 로컬 저장소의 커밋 작성자는 `MJbae <gentlygogo@gmail.com>`을 사용한다.

GitHub Pages는 HTML·CSS·JavaScript 정적 파일을 배포하며, 프로젝트 주소는 `https://<owner>.github.io/awon-repair-refund/` 형식이다. 무료 개인 플랜을 사용할 경우 공개 저장소 구성을 기본으로 검토한다. [GitHub Pages 개요](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

배포 순서는 다음과 같다.

1. 계산기와 검증을 완료하고 원본·개인자료가 Git 추적에 들어가지 않았는지 확인한다.
2. 원격 저장소 생성·연결 후 소스와 비식별 기초자료를 푸시한다.
3. 저장소 `Settings → Pages → Source`를 `GitHub Actions`로 지정한다.
4. `main` 푸시 또는 수동 실행 시 데이터 검증 → 계산 테스트 → `site/`만 `dist/`로 복사 → Pages 업로드·배포를 수행한다.
5. 배포 job에 필요한 `contents: read`, `pages: write`, `id-token: write` 권한과 `github-pages` 환경을 구성한다. Action 버전은 구현 시 공식 권장 버전을 확인한다.
6. 저장소 하위 경로에서 자산·JSON 경로, HTTPS, 모바일 입력, 법령 링크, 두 상세 영역 펼치기를 확인한다. 데이터 변경도 같은 검증·배포 흐름을 거친다.

공식 Actions 흐름은 [GitHub의 게시 원본 설정 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 따른다. 모든 자산 경로를 프로젝트 하위 경로에서 동작하게 만들고 서버 라우팅이 필요한 URL은 만들지 않는다. 배포 실패 시 마지막 정상 버전을 유지하고 잘못된 데이터는 변경을 되돌린 커밋으로 재배포한다.

`.gitignore` 외에도 배포 산출물을 허용된 `site/` 파일로만 구성한다. 저장소 루트 전체를 업로드하지 않는다. 원본 사진과 로컬 판독표는 공개 저장소에도 Pages 산출물에도 포함하지 않는다.

구현은 약 2.5~4.5 작업일로 예상한다. 합의한 가정으로 개발을 진행하고, 추가 자료 확보를 기다리지 않는다. 제공받은 전체 호수별 면적을 자동 적용하고 추정 계산임을 표시한다. 추가 자료가 확보되면 출처와 함께 기본 데이터를 보완한다.

계산 및 데이터 검증의 필수 사례:

- 면적 타입 세대수 합이 14이고 공급면적 합이 1,763.07㎡인지 확인한다. 면적 자료 교체 시 기대값도 출처와 함께 갱신한다.
- 공급·전유 기준의 분자·분모가 섞이지 않고, 전유면적 합계 1,591.29㎡ 및 지분 조정이 맞는지 확인한다. 적용 제도가 미확인인데 특정 법령의 확정 청구로 출력되지 않는지 검증한다.
- 시작월 첫 입력 또는 마지막 월 첫 입력에서 반대편 빈 칸만 24개월로 채워지는지, 이후 수정 시 반대편 값이 유지되는지 확인한다. `24개월로 맞추기`는 시작월을 유지해야 한다.
- 2024-10~2026-09가 정확히 24개월인지, 같은 월 1개월·연도 경계·역전·빈 입력을 처리하는지 확인한다. 연도·월 드롭다운으로 과거 연도를 선택하고 총개월 수를 즉시 이해할 수 있는지 점검한다.
- 예시 28만 원·149.68㎡·24개월의 최종 반올림 결과가 570,510원인지 독립 검산한다. 세대별 반올림 전 배분액의 합이 단지 월 적립액과 일치하는지 확인한다.
- 2024-01~2026-12는 36개월 기본 구간이며 그 안에서 선택한 24개월만 합산되는지 확인한다. 기본 가정을 사용할 때 월별 증빙이나 추가 동의를 요구하지 않아야 한다.
- 중간에 적립액이 바뀐 경우 각 월에 해당 금액이 적용되는지, 구간 경계·중복 검증·개별 월 수정 우선순위가 맞는지 확인한다.
- 기간 축소 후 재확장 시 수정값이 복구되는지, 호수 변경 시 단지 금액과 기간은 유지되며 다른 세대의 직접 납부액이 섞이지 않는지 확인한다.
- 귀속월이 다른 동일 호수 입금 2건, 분할납, 소유자 직접 납부, 반환 완료액을 중복 청구하지 않는지 확인한다.
- 사용자 승인 가정과 실제 증빙을 구별한다. 2023년·2027년 등 기본 범위 밖의 미입력 구간은 0원 처리하지 않으며, 이용자가 28만 원을 확장 적용하거나 직접 금액을 넣을 수 있어야 한다.
- 미래 월은 납부 완료 합계에 들어가지 않고 향후 예상액으로 분리되는지 확인한다. 정산 기준월을 고정한 검증에서도 같은 결과가 나와야 한다.
- 실제 대납액이 자동 면적 추정액보다 우선하는지 확인한다. 14개 호수의 결과와 이전 저장 면적 무시 동작을 검증한다.
- 부분월·윤년 2월·날짜 포함 기준을 검증하고 일할 추정과 실제 이사 정산액을 구분한다.
- 두 상세 영역의 펼침·접기, 기간에 맞는 월별 내역, 14호 면적표, 법령의 최하단 배치를 확인한다.
- 배포 산출물과 Git 추적 파일에 사진·주민 실명·계좌번호·세대별 사적 납부이력이 없는지 확인한다.

## 10. 후속 보완 항목

호수와 납부 기간은 이용자가 서비스에서 입력한다. 월 28만 원의 2024~2026년 적용, 관리비 포함 납부, 순번 총무·공용 통장 운영은 사용자 답변으로 반영했다. 이를 다시 확인하거나 특정인의 호수·입주일을 요청할 필요가 없다. 아래 자료는 정확도를 높이기 위한 선택적 보완이며 구현·계산의 선행 조건이 아니다.
