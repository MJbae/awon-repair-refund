# 계산 정밀도 검증

검증일: 2026-09-17. 실행 명령과 독립 참조 계산기를 저장소에 포함했다.

## 결론

검증한 범위에서 면적 비례 금액 산식의 오산은 발견하지 못했다. 다만 입력 중인 월별 금액·반환금이 계산에 늦게 반영되는 UI 문제, 잘못된 쉼표 입력의 묵시적 변환, 실제 처리와 다른 설명을 발견해 수정했다.

`70.81㎡ ÷ 1,763.07㎡`의 정확한 비율은 `7081/176307`, 소수로 `0.040162897672…`, 백분율로 `4.0162897672…%`이다. **약 4.02%는 소수 둘째 자리까지 반올림한 올바른 표시**다. 수식에는 근삿값 기호 `≈`를 사용하고 소수 비율 8자리와 백분율 4자리를 함께 표시하도록 개선했다.

금액 계산에는 표시된 백분율을 사용하지 않는다. 원 단위 정수와 0.01㎡ 단위 정수를 BigInt 유리수로 계산한 뒤, 대상 월들의 원 미만 금액까지 합산하고 마지막에 원 단위 반올림한다. 실제액을 직접 입력한 달은 그 정수 금액을 우선한다.

## 601호 예시

월 단지 금액 280,000원, 공급면적 70.81㎡, 총면적 1,763.07㎡, 24개월을 모두 납부했다고 가정한다.

| 방법 | 24개월 금액 | 판정 |
|---|---:|---|
| 정확한 면적 비율로 월별 계산 후 합산·최종 반올림 | **269,895원** | 서비스 계산 방식 |
| 표시된 월 11,246원을 먼저 반올림해 24배 | 269,904원 | 9원 과다 |
| 표시된 백분율 4.02%로 금액을 역산 | 270,144원 | 249원 과다 |

월의 정확한 계산값은 약 11,245.611348원이다. 월별 표는 읽기 위해 11,246원으로 표시하지만 계산에는 원래 분수를 사용한다. 화면에는 표시액 합과 정산액에 차이가 있으면 그 차이도 설명한다.

## 14세대 기준 검산값

동일하게 월 280,000원, 과거·현재에 해당하는 완전한 24개월, 별도 수정·반환금이 없는 조건이다.

| 호수 | 공급면적 ㎡ | 월 표시액 | 24개월 최종액 |
|---|---:|---:|---:|
| 101·102·201·202·301·302·401·402 | 149.68 | 23,771원 | 570,510원 |
| 501 | 117.04 | 18,588원 | 446,102원 |
| 502 | 144.37 | 22,928원 | 550,271원 |
| 601 | 70.81 | 11,246원 | 269,895원 |
| 602 | 114.27 | 18,148원 | 435,544원 |
| 701 | 36.22 | 5,752원 | 138,054원 |
| 702 | 82.92 | 13,169원 | 316,052원 |

14세대 공급면적 합계는 정확히 1,763.07㎡이며, **반올림 전** 세대별 배분 합은 단지 금액과 정확히 일치한다. 각 세대 결과를 별도로 반올림해 합치면 월 금액은 279,999원, 24개월은 6,719,998원으로 단지 총액보다 각각 1원·2원 작다. 이는 세대별 독립 반올림의 잔여다. 단지 전체의 원 단위 잔여금을 특정 세대에 강제로 배분하지 않는다.

과거·미래 소계도 각각 최종 반올림하므로, 두 표시 소계의 합과 전체를 한 번에 반올림한 값이 1원 다를 수 있다. 예를 들어 과거 0.5원·미래 0.5원은 각각 1원으로 표시되지만 전체 합은 1원이다. 반환 참고액은 과거·현재 금액만 사용하며 미래 금액을 더하지 않는다.

## 테스트 계층

| 검증 | 범위 | 결과 |
|---|---|---|
| Node 자동 테스트 | 계산·입력·표시·경계 51개 테스트 그룹 | 전부 통과 |
| 독립 Python 참조 계산 | 정상 1,641개 사례, 45,050개 월별 행 | 불일치 0건 |
| 독립 입력 거부 검증 | 잘못된 기간·금액·면적·부분월 등 62개 사례 | 모두 거부 |
| 결함 주입 테스트 | 현실적인 산술 오류 9종 | 9종 모두 탐지 |

Python 참조 계산은 JavaScript 함수를 불러오지 않고 표준 라이브러리 `fractions.Fraction`, `calendar.monthrange`로 기대값을 생성한다. 난수 시드는 `20260917`로 고정하여 재현 가능하게 했다. 실제 애플리케이션의 결과와 월별 행, 과거·미래·실제·추정 합계, 반환금, 누락월, 입력 불변성을 비교한다. 큰 JSON 자료는 임시 폴더에서 생성하고 검증 후 삭제한다.

경계 검증에는 0원·1원·월 1조 원, 1개월·24개월·36개월·600개월, 최대 안전 정수 면적, 0.5원 반올림, 28·29·30·31일, 1900·2000·2100년 윤년 규칙, 당월·미래월 경계가 포함된다. 기준일은 한국 시간의 현재 월로 구분하며 독립 검산은 기준월을 고정한다.

금액 변경은 개별 월 > 변경 구간 > 일괄 입력 > 기본값 순으로 검증한다. 실제액 대체, 소유자 납부 제외, 기간 축소·재확장, 호수 변경, 부분월 양 끝 날짜 포함, 실제액에 대한 중복 일할 적용 방지, 과도한 환급액 거부도 다룬다.

## 수정한 결함

1. 금액·실제액·부분월 날짜를 입력하는 중에는 이전 결과를 즉시 숨기고, 포커스를 유지하면서 계산값에 반영한다. `change` 이벤트나 다른 곳 클릭을 기다리지 않는다.
2. 반환금의 입력 원문과 오류를 호수별로 유지한다. 도구 호출도 입력 중인 반환금을 반영하고, 잘못된 값은 호수 변경으로 사라지지 않는다.
3. 실패한 재계산 뒤에 이전 성공 결과를 표시하지 않는다. 반환금 오류를 수정하면 오류 메시지도 해제한다.
4. `28,00`, `1,2,3` 등 잘못된 쉼표 입력을 다른 금액으로 변환하지 않고 거부한다.
5. 잘못된 기본 기간·월별 자료 형식·납부 모드를 면적 추정으로 묵시적으로 처리하지 않는다.
6. 소유자 납부로 제외한 결과를 실제 납부액 합산으로 설명하지 않는다. 계산식·기본 금액·기간·총면적 설명을 데이터와 연결한다.
7. 표시용 비율과 원 미만 금액의 최종 반올림 정책을 명확히 설명한다.

## 오류를 잡아내는지 검증

원본 파일은 바꾸지 않고 임시 복제본에 다음 결함을 각각 주입했다.

- 월별 금액을 먼저 반올림한 뒤 합산
- 부분월의 하루 누락
- 현재 월을 미래 월로 분류
- 반올림된 백분율로 금액 계산
- 미래 예상액을 반환 참고액에 합산
- 0원 덮어쓰기 무시
- 마지막 납부월 제외
- 모든 달을 30일로 계산
- 반올림 대신 버림

9가지 모두 독립 기대값과의 비교에서 실패하여 검출됐다.

## 재현

Node.js 22 이상과 Python 3.10 이상이 필요하다. 배포되는 계산기에는 Python 의존성이 없다.

```sh
npm ci
npm run check
npm run test:mutations
```

`npm run check`에는 독립 정밀 검산도 포함되어 GitHub Actions에서 매 변경마다 실행된다. 테스트는 산식과 구현의 정확성을 검증하며, 단지 월 금액·납부 사실 등 입력 자료의 실재성을 증명하는 것은 아니다.
